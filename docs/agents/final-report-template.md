# Шаблон финального отчёта агента

Используй этот формат в конце задачи, чтобы Владыка сразу видел реальный статус.
Перенесён из PostEditBot, дополнен полями route-цикла и Plane.

```md
Статус: готово локально / запушено / задеплоено / проверено на бою

Plane: TGSUPBOT-<N> — создана / обновлена / Plane недоступен: <причина>.

Триаж: лёгкая / средняя / сложная. Кругов ревью: <n>. Codex session: <uuid или «не использовался»>.

Commit:

- `<sha>` / не создан: `<причина>`.

Push:

- `origin/main` обновлён / не выполнен: `<причина>`.

Изменено:

- `<файл или зона>` — что и зачем изменено.

Проверено:

- `<команда>` — успешно / результат.

Не запускалось:

- `<команда>` — почему пропущено.

Чужой WIP:

- Нет / не трогал: `<файлы>` / блокер: `<причина>`.

Deploy:

- Не выполнялся.
- Или: выполнен `<команда>`, проверено `docker compose ps` / `poller-health` / логи.

Принятые решения:

- X, потому что Y.

Nit'ы (не блокируют):

- <файл:строка> — замечание.

Риски/заметки:

- Коротко указать, если есть предупреждения, старые warning или ручные шаги.
```

## Запреты в отчёте

- Не писать «на бою», если не проверены Docker-сервисы, poller-health и актуальный commit.
- Не писать «тесты прошли», если запускались не через `.\scripts\run-isolated-tests.ps1`
  или `.\scripts\project-tools.ps1 quality|test`.
- Не писать «запушено», если `git push` не выполнялся.
- Не выдумывать номер Plane-задачи, если Plane был недоступен.
- Если агент менял файлы, не завершать отчёт без `Commit` и `Push` либо точного блокера.

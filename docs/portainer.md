# Portainer CE на Ubuntu-ВМ

Portainer — веб-интерфейс для Docker на ВМ 101. В нём удобно смотреть
состояние контейнеров и их журналы, а при необходимости — перезапускать контейнер.
Он работает отдельным Compose-проектом `portainer`, без подключения к сетям
и томам других проектов.

## Адрес и первый вход

Откройте https://192.168.1.101:9443 из домашней сети.
Браузер предупредит о самоподписанном сертификате: для этого адреса это ожидаемо.
Владелец сам создаёт администратора в браузере в течение 5 минут после старта.
Если окно истекло, оркестратор перезапускает контейнер, затем владелец повторяет вход.

## Правила работы

В интерфейсе смотрим состояние и журналы, при необходимости перезапускаем контейнер.
Настройки, образы и состав стека бота меняем только через репозиторий
и `deploy-proxmox.ps1`. Изменения кнопками не записываются в файлы репозитория
и расходятся с ними; следующий деплой может их заменить.

Для боевого стека `tg-support-bot` запрещено:
- удалять контейнеры и тома;
- пересоздавать контейнеры или стек;
- менять переменные окружения;
- запускать консоль с командами, меняющими базу данных.

Доступ к `docker.sock` равен полному доступу к серверу, даже при
`no-new-privileges`. Владелец осознанно выбрал такой инструмент.
Интерфейс наружу не публикуется: порт 9443 не пробрасывается на роутере
и не публикуется через обратный прокси Synology. Порты 9000 и 8000 не открываются.

## Установка и обновление — только оркестратором

Оркестратор создаёт `/home/karshiev/portainer` и копирует туда
`scripts/vm/portainer/docker-compose.yml` из репозитория.
В этом каталоге запускает `docker compose up -d`.
Закреплён образ `portainer/portainer-ce:2.45.2`.
Для обновления сначала меняется закреплённая версия в репозитории,
затем оркестратор копирует файл на ВМ и повторяет `docker compose up -d`.

## Данные и резервные копии

Данные хранятся в именованном томе `portainer_data` (Compose создаёт
его с префиксом проекта: `portainer_portainer_data`). Том копируется
вместе со всей ВМ в ночной резервной копии `vzdump`.

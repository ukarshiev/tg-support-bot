# Домашний доступ к сервисам

## Что это

Домашние сервисы открываются по именам на `karumweb.ru`, с настоящим сертификатом и только из домашней сети. Вне дома доступ планируется через VPN на Keenetic; VPN ещё не настроен.

`plane.karumweb.ru` и `care-support.relaxa.club` остаются публичными, со своими сертификатами. Их настройки не менять.

## Адреса

| Имя | Сервис |
|---|---|
| `pve.karumweb.ru` | Proxmox |
| `docker.karumweb.ru` | Portainer |
| `plex.karumweb.ru` | Plex |
| `synoserv1.karumweb.ru` | Synology DSM |

## Как идёт запрос

Браузер открывает имя → публичная A-запись ведёт на домашний адрес `92.101.120.247` → Keenetic → Synology `192.168.0.101:443` (обратный прокси). Для Proxmox и Portainer запрос дальше идёт через Cudy `192.168.0.3` к серверу за ним.

С 09.10.2026 DNS домена `karumweb.ru` обслуживает Cloudflare (`naya.ns.cloudflare.com`, `weston.ns.cloudflare.com`); регистратор — reg.ru. Все записи должны быть в режиме «Только DNS» (серое облако). Почты на домене нет: TXT записи `v=spf1 -all` и `_dmarc` со значением `v=DMARC1; p=reject; sp=reject; adkim=s; aspf=s`.

## Настройки по устройствам

### Cloudflare

- Для имён сервисов — публичная A-запись на `92.101.120.247`, «Только DNS».
- Проксирование Cloudflare не включать: Synology тогда не увидит адрес посетителя и ограничение «только из дома» перестанет работать. Кроме того, в России трафик через Cloudflare замедляется.

### Cudy

В `Firewall → Port Forwards` оба новых правила разрешают источником только Synology `192.168.0.101`:

| Правило | Адрес и порт Cudy | Назначение |
|---|---|---|
| Portainer | `192.168.0.3:9443` | `192.168.1.101:9443` |
| Proxmox web | `192.168.0.3:8006` | `192.168.1.102:8006` |

Старые правила `Proxmox` и `SMB PVE` на адресе `192.168.0.102` оставлены как были.

### Synology

Обратный прокси: `Панель управления → Портал для входа → Дополнительно`. У каждого правила источник — HTTPS, порт `443`, соответствующее имя; профиль доступа — `home-only`, заголовок WebSocket включён.

| Имя | Назначение |
|---|---|
| `pve.karumweb.ru` | HTTPS `192.168.0.3:8006` |
| `docker.karumweb.ru` | HTTPS `192.168.0.3:9443` |
| `plex.karumweb.ru` | HTTP `localhost:32400` |
| `synoserv1.karumweb.ru` | HTTPS `localhost:49999` |

Профиль `home-only` разрешает `192.168.0.0/24` и `192.168.1.0/24`, всем остальным запрещает доступ. WebSocket нужен для консолей машин и контейнеров. Отдельное правило для `synoserv1.synology.me` (вход в DSM из интернета) существует отдельно — профиль `home-only` на него не назначать.

## Сертификат

Один сертификат Let's Encrypt выпущен на `synoserv1.karumweb.ru` с альтернативными именами `docker`, `plex` и `pve`; действует до 07.01.2027. DSM сам выдаёт и продлевает его через HTTP-01. Для проверки HTTP-01 порт 80 домашнего адреса открыт из интернета.

Привязки задаются в `Безопасность → Сертификат → Настройки`: четыре строки имён `karumweb.ru` должны использовать этот сертификат.

## Как проверить

- Дома откройте нужное имя в браузере.
- Проверка «из интернета» оркестратором выполняется с ВМ одноразовым контейнером `curl` в сети `openclaw-proxy`, через `--socks5 xray-egress:10808` и `--resolve имя:443:92.101.120.247`.
- Пробросы Cudy из внутренней сети проверить нельзя: они разрешают источником только Synology. Проверяйте весь путь через имя.

Проверка 09.10.2026: все четыре имени открывались из дома с совпадающими именем и цепочкой сертификата; из интернета все четыре отвечали `403`. Plane и `care-support` не затронуты.

## Как добавить новое имя

1. Добавить в Cloudflare A-запись на `92.101.120.247` с режимом «Только DNS».
2. Если нужно, добавить проброс на Cudy с источником `192.168.0.101`.
3. Создать правило обратного прокси на Synology с профилем `home-only` и WebSocket.
4. Выпустить новый сертификат с полным списком имён: добавить имя в существующий сертификат нельзя.
5. Назначить новый сертификат в «Настройки», затем удалить старый сертификат.

## Грабли

1. Адрес Cudy `192.168.0.102` работает только внутри сети Cudy. Synology до него не достаёт — через три секунды будет `502`. Используйте `192.168.0.3`.
2. DSM иногда показывает «Операция невозможна. Выполните вход в DSM», хотя сертификат уже выдан. Сначала проверьте список сертификатов и не повторяйте запрос: Let's Encrypt ограничивает выдачу пятью одинаковыми сертификатами в неделю.
3. У reg.ru DNSSEC на собственных DNS-серверах включается незаметно. При переезде `karumweb.ru` reg.ru снял подпись сразу, а реестр удалил отпечаток примерно через 35 минут; Google, Cloudflare и Quad9 ещё несколько часов отказывали по всему домену, включая Plane. Перед переездом другого домена проверьте `dig DS <домен> @a.dns.ripn.net` и сначала снимите подпись.
4. Сервер Plex на Synology нужно привязать к учётной записи через `http://192.168.0.101:32400/web`. Пользователю `PlexMediaServer` нужны права чтения на каждую общую папку.
5. При первом входе Portainer просит setup token из журнала контейнера. После каждого перезапуска токен меняется.

На Synology владелец включил двухфакторный вход и автоблокировку. У агентов нет доступа к Synology, Cudy, Keenetic, Cloudflare и reg.ru: настройки вносит владелец по инструкции, агент проверяет результат.
